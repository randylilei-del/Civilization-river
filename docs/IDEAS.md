# 产品想法库

**这个文件存的是「想清楚了但现在不做」的东西。** 与 HANDOFF.md 的区别：HANDOFF 是临时现场快照、
任务完成即删；这里的条目是长期的，**等触发条件到了要被主动拿出来讨论**。

每条必须写清四件事：**灵感来源 / 已做的分析 / 触发条件 / 为什么现在不做**。
分析写足——目的是将来接手时不用重新想一遍。

## 💡 001 · 从「浏览一条长河」到「回答孩子的问题」

**状态**：**层一已上线（v152，2026-08-15，Ray 拍板提前做）**——搜索框 + `SEARCH_ALIAS` 别名表（10 条起步）+ 结果直接显示命中句，搜索词落 localStorage `whviz-sq` 当层三的采集探针。**层二（story 页覆盖面）与层三（故事级颗粒）仍按原触发条件等实验结论**；下一步就是原文写的：用 `whviz-sq` 里的真实搜索词决定层三从哪几个「东西」开始做。
原始分析保留如下（层一的实测数据仍是层三的证据）。
**来源**：2026-08-10，Ray 问「小朋友结合他接触到的新知识来找答案，我们能不能满足？
比如最近很火的电影《奥德赛》，他想了解更多」

### 问题的形状

站是按「**文明 × 时间**」组织的，是**浏览式**产品。
但孩子的真实入口是**具体的东西**——一部电影、一个金面具、一只恐龙、一句在学校听来的话。
他嘴里的词（奥德赛、木马屠城、宙斯）和站里的词（米诺斯·迈锡尼、线形文字 B）对不上。

### 已做的分析：三层缺口，性质完全不同

**层一 · 找得到吗？→ 现在不行，但最容易补。**

拿《奥德赛》实测：**内容其实在站里**——米诺斯·迈锡尼卡明写「特洛伊战争传说即以这个时代为背景」，
大事记有「前1250 特洛伊战争的时代 · 荷马唱的正是这批迈锡尼王的远征」，古希腊有「前800 荷马史诗写定」。
**但全站没有搜索框**（`index.html` 里的 `search` 只有 B 站/YouTube 外链）。
孩子要找到它，得先知道「奥德赛属于迈锡尼时代、前 13 世纪、欧洲泳道」——正是他要问的东西。
**「知道了才查得到」的死循环。**

2026-08-10 用全文扫描模拟搜索，命中率其实不错（这批数据是这条想法的证据，别丢）：

| 孩子会输入 | 现有数据能给什么 |
|---|---|
| 特洛伊 / 荷马 | ✅ 米诺斯·迈锡尼卡 + 两条大事记 |
| 金字塔 | ✅ 四个文明（埃及/库施/玛雅/特奥蒂瓦坎）——顺带教会「金字塔不止埃及有」 |
| 斗兽场 / 兵马俑 / 奥运会 | ✅ 都能落到具体条目（含成就卡、地点小段） |
| 奥德赛 / 木马 / 木乃伊 / 恐龙 | ❌ 零结果或跑偏（奥德赛只命中亚历山大城的地点小段） |

**做法**：搜索框 + **别名表**（奥德赛→特洛伊、木马屠城→特洛伊…，仿照已有的 `GC_ALIAS` 城市古称机制）
+ **结果直接显示命中的那句话**，不是只跳整张卡——即使内容只有一句，孩子也拿到一个答案而不是一张读不懂的卡。
成本：一天内，**不写任何新内容**，纯利用已核数据。

**层二 · 找到了看得懂吗？→ 一半。**
搜到「米诺斯·迈锡尼」，他看到的是给 Ray 写的卡片（六问、线形文字 A/B、宫殿经济）。
真正给孩子写的是 story 页，但目前只有六个中国朝代（tang/qin/han/song/ming/qing）。

**层三 · 颗粒度对不对？→ 这才是根本问题。**
站的最小单位是**文明**；孩子的入口是**具体的东西**。「奥德赛」在站里只是半句话——
搜到了也就是半句话，不是一个答案。要真正回答「奥德赛是什么」，需要**故事级颗粒**
（像成就卡/人物卡那样，但覆盖面要广得多）。140 个文明铺开是另一个量级的工程。

### 触发条件（满足任一即可拿出来讨论）

1. **主体工程完成之后**——Ray 明确说的时点。数据迁移（Phase 1-4）已完成；
   剩下的主体待办是国内访问部署、VIDEO 补全、story 实验收口。
2. **唐朝/六朝实验有结论之后**——如果实验证明「问题驱动」有效，层二层三的答案会跟着变。
3. **Jasper 真的问出「XX 是什么」而站里答不上来**——这是最强的信号，比任何推理都值钱。

### 为什么现在不做

- 实验材料（六页）刚发出去，`docs/TANG-EXPERIMENT.md` 写死了「结果出来前不加功能」。
  一次只改一个变量，实验才干净。
- 层一的搜索**顺带能采集 Jasper 搜什么词**——但那要等他先用起来。他搜的词会直接告诉我们
  层三该从哪几个「东西」开始做，比我们拍脑袋选强得多。

### 下次讨论时的建议起点

先做层一（搜索 + 别名 + 显示命中句），把它当**探针**而不是终局功能：
用真实搜索词决定层三做什么。**不要一上来就规划 140 个文明的故事级内容。**

## 💡 002 · 「共同体」——欧盟这类东西该怎么画

**状态**：**已完成——v143 欧盟原型、v144 东盟与非盟补齐，三条都在图上了**（这一条可视为收口，留档备查）
**来源**：2026-08-14，v135 排查「国家还在但色带结束了」时，Ray 说「欧洲我在想，
其实欧盟这个很重要的其实反倒是欧盟——你觉得应该怎么体现？同样的其他区域是否有类似的
区域自治共同体？」

### 问题的形状

先是一个可查证的缺口：**欧洲是八条泳道里唯一没有「现代收尾带」的。**

| 泳道 | 画到 2025 的带 |
|---|---|
| 东亚 | 共和国、日本、韩国 |
| 东南亚 | 现代东南亚 |
| 南亚 | 印度·南亚诸国 |
| 草原·中亚 | 现代中亚 |
| 中东·北非 | 现代中东 |
| 撒南非洲 | 现代非洲 |
| 美洲 | 美国、拉丁美洲诸国 |
| **欧洲** | **只有英、法、德、俄四条单独画到 2025** |

后果：孩子把时间轴拉到今天看欧洲，看到的是「欧洲今天只剩四个国家」——荷兰、意大利、
西班牙、葡萄牙、希腊、奥地利、波兰、瑞典**全部停在历史里**。v135 的改名只解决了
「名字误导」，**没解决「今天它们去哪了」**。

**但 Ray 的再定义比「补一条现代欧洲」准**：欧洲今天真正的新东西不是「又一个国家」，
是**一群仍然存在的国家自愿把一部分主权交上去**。这在整条长河里是个**新形状**。

### 已做的分析

**① 为什么它不该是色带。** 站里现在只有两种表达语法：色带 = 一个政权在时间里的兴衰；
轨迹 = 一样东西沿线传播。欧盟两个都不是。硬做成色带有两个具体的害处：
- 它会和英法德俄四条并排叠着，**被读成「欧洲又多了一个国家」——正好教错**；
- 英国 2020 退出了，**色带表达不了「进去又出来」**。

**② 三个选项，倾向第三个。**
- **当色带**：见上，不建议。
- **当事件**（复用已有的 22 个交流事件机制）：1993 马斯特里赫特条约 / 2002 欧元流通 /
  2020 英国脱欧。省事，但**太轻**——事件是一个时间点，共同体是一个持续的结构。
- **当成新的一层「共同体」**：视觉上是**横跨多条色带的一道括号或底纹**，明说「这几个
  国家还在，但它们上面还多了一层」。**这一画，荷兰/意大利/西班牙/波兰这些名字就以真实
  身份重新出现在今天**，顺带把上面那个缺口一并解决。

给 7 岁的说法可以很硬：**「这些国家还在，但他们说好了很多事一起决定，钱也用同一种。」**
——欧元是最好的抓手，孩子对「钱能不能通用」有直觉。

**③ 其他区域有没有类似的？有，但分量差得很远，别一视同仁。**
唯一有意义的尺子是**主权让渡的深度**：

| 共同体 | 起 | 让渡了什么 | 判断 |
|---|---|---|---|
| **欧盟** | 1993（前身 1957 罗马条约） | 共同货币 + 共同法律 + 人员自由流动 + 超国家法院 | ✅ 唯一真正让渡主权的 |
| **东盟 ASEAN** | 1967 | 协商与不干涉，**明确不建超国家机构** | ⚠️ 可做，但必须说清它和欧盟不是一回事 |
| **非洲联盟 AU** | 2002（前身 OAU 1963） | 共同议程与维和部队，成员国主权完整 | ⚠️ 同上；**总部在亚的斯亚贝巴**，正好接得上埃塞俄比亚帝国那条 |
| 南方共同市场 / 海合会 / 独联体 / 欧亚经济联盟 | — | 关税与安全协调 | ❌ 太细，7 岁没有抓手 |

**结论：只做欧盟、东盟、非盟三个**，正好各自对应站里已有的收尾带（现代东南亚、现代非洲），
欧洲那条补上缺口——**三条泳道各画一道括号，形状统一**。不做南美/中东/北美的理由不是它们
不重要，是**给孩子的东西必须能一句话说清「他们一起做了什么」**，这几个说不清。

### 触发条件（满足任一即可拿出来讨论）

1. **六页故事实验出结论之后**——`TANG-EXPERIMENT.md` 写死了「结果出来前不加功能」。
2. **有人（Jasper 或别人）问出「欧洲今天怎么只剩四个国家」**——那说明缺口已经被看见了。
3. **下一次要动主站视觉语法时**——共同体层该和那次改动一起设计，不要单独插一层。

### 为什么现在不做

- 它要**新增一层视觉语法**（横跨色带的括号），是这个站到目前为止最大的一次表达方式扩展，
  比 v135 改名重得多；改错了会污染所有泳道的读法。
- 实验期不加功能的边界还挂着。

### 下次讨论时的建议起点

**先只画欧盟一条，当原型**，看横跨括号在时间轴上到底好不好读（这条泳道最挤：括号要同时
横跨英法德俄四条已有的带，还要把荷兰、西班牙那些**已经结束的**带在今天重新点亮——这是
最难的一格，画得通，东盟非盟就是照抄）。**不要三条一起上。**

## 💡 003 · 「探索模式」——掷骰子式的随机穿越

**状态**：待讨论（2026-08-16 提出，分析已做，等触发条件）
**来源**：2026-08-16，Ray：「我们现在不是加了一个引导界面吗，它相当于是第一次让大家知道
怎么用这个页面。我在想能不能加一个探索模式，他点了几次之后，每天有点像掷骰子一样，
可以自动穿越到历史当中的某一个文明、或者某一个城市去看它的前世今生，或者穿越到某一条
哲学、宗教的传播线路，然后顺着这个去学习和探索。但是这个东西怎么放到页面的入口处展现、
还有产品逻辑，我还没想清楚。」

### 问题的形状

**搜索是被动的，探索是主动的。** 001 层一（搜索框，v152 已上线）解决的是「他想知道 X，
找不找得到」；但孩子打开这个站，**多数时候并没有具体想找的东西**，只能「浏览一条长河」，
而浏览对 7 岁来说很快就没劲。

探索模式给的是**一个点下去的理由**。两者互补，不重复：
搜索答「我想知道 X」，探索答「**我不知道我想知道什么**」。

### 已做的分析

**① 站里已经有一个原型，但它很窄。**

`#gvRand`「随便去个地方 / Surprise me」（`index.html` 的按钮定义与 click 处理）：
均匀随机抽 `GEO_CITY` 的 127 城，`gvQuery` 跳过去。三个局限：
**只活在地理视角内**（另外两个视角看不到它）、**只跳城市**（不跳文明、不跳轨迹）、
**均匀随机、不加权**。

**② 随机池必须加权——而且文明和城市的情况正好相反。**

按「掷到它、点进去之后还有没有东西可以再点」（成就卡 + 人物卡）给 159 个文明分档：

| 档 | 文明数 | 掷到之后 |
|---|---|---|
| A（≥3 张可点卡） | **49** | 有得点，待得住 |
| B（1—2 张） | 83 | 一张卡加一两个点 |
| C（0 张） | **27** | **只有一张卡，没有任何可再点的东西** |

C 档里有米诺斯·迈锡尼、印度河文明、二里头·夏、奥尔梅克、查文文化、五代十国这些。
照片覆盖 144/159，**视频只有 33/159**。

**城市那边反过来**：127 座里 **126 座**都有 ≥4 段地点小段 + 照片 + 古迹（唯一的例外是
金沙萨，2 段）。

→ **城市池几乎不用筛，文明池必须筛。** 这解释了现有 `gvRand` 只跳城市为什么是安全的，
但也解释了它为什么最没惊喜：城市面板本来就是「按地方看」的主内容，掷骰子只替他省了一次点击。

**③ 三种穿越对象的成本差一个量级，别捆在一起。**

| 穿越到 | 现状 | 成本 |
|---|---|---|
| 某个文明 | 卡片现成 | 近乎零（但要过 ② 的筛） |
| 某座城市 | 六层面板现成 | 近乎零 |
| **某条传播线路** | 33 条轨迹**只是图上的线**，没有「顺着走一遍」的交互 | **这是新功能，不是复用** |

**④ 真正的难点不是「怎么跳」，是「跳过去看什么」。**

掷到唐朝就直接打开唐朝卡片——那跟他自己点开唐朝没有区别，骰子只是个花哨的随机跳转。
要有价值，**落地页必须不一样**：给一个具体的钩子问题（「唐朝的长安城里住着多少外国人？」），
而不是一张卡。

**而这正好撞上 001 的层三（故事级颗粒）。** 好消息是：探索模式给层三提供了一个**比铺
159 个文明便宜得多的切入点**——只要给 A 档那 **49 个**各写一个钩子问题就够了。

**⑤ 入口不该是第四个视角。**

「按时间看 / 按地方看 / 按列表看」是三种**看法**，探索是一个**动作**。放进视角切换器
会被读成第四种浏览方式。倾向：**一个常驻小按钮，三个视角下都能点**（现在的 `gvRand`
只在地理视角内，要提出来）。

**⑥「每天一次」是留存机制，不是探索机制。**

它假设 7 岁孩子有「每天打开一个 app」的习惯——**这个假设该验证，不该直接设计进去**。
建议先做成不限次数的「再掷一次」，**看他实际掷几次**，再决定要不要加每日限制。
（这与 001 层一「把搜索当探针」是同一个思路：先采数据，再定功能。）

### 触发条件（满足任一即可拿出来讨论）

1. **唐朝实验出结论之后**——落地页该长什么样，取决于「他愿不愿意被带着走六幕」这个结论。
2. **Jasper 用 `gvRand` 用出规律**——这个按钮**已经在线上了**，可以先看他点不点、点几次。
   这是零成本的探针，比任何推理都值钱。
3. **001 层三启动时**——两者共用「钩子问题」这批内容，必须一起设计，不要各写一套。

### 为什么现在不做

- `docs/TANG-EXPERIMENT.md` 写死了「结果出来前不加功能」，一次只改一个变量，实验才干净。
- 落地页设计依赖实验结论（见触发条件 1），现在做等于拍脑袋。

### 下次讨论时的建议起点

**先只把 `gvRand` 改成加权 + 提到全站常驻**，不加任何新内容。这是半天的事。
⚠ **它算不算「加功能」需要 Ray 判**——我倾向算「既有功能的修正」而不是新功能，
但这条边界是实验纪律划的，我不自己越。

真正要讨论的是落地页：**先给 A 档 49 个各写一个钩子问题**，还是等 001 层三一起做。
**不要一上来就做传播线路的「顺着走一遍」**——那是三者里唯一真正的新功能。
