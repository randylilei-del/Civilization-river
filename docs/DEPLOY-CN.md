# 国内访问方案

**为什么有这份文档**：这个站是给儿子做的，他在上海用 iPad。
现在的地址 `civilization-river.vercel.app` 在国内**必须挂 VPN 才打得开**——
也就是说「整个项目给孩子做的，而他打不开」。这份文档解决这件事。

> 状态：**方案已查清、代码侧已确认零改动，但没有实测**（本机不让绕代理发请求）。
> 注册与实名认证必须 Ray 自己做，Claude 不碰身份证类信息。

---

## 一、代码要改什么：什么都不用改

已逐项确认过：

| 项 | 现状 | 换域名后 |
|---|---|---|
| `manifest.webmanifest` | `start_url` / `scope` 都是 `./`，图标是相对路径 | 照常工作 |
| `sw.js` | 用 `self.location.origin` 判断同源，资产清单全是相对路径 | 照常工作 |
| `index.html` | 单文件，无构建、无后端、无外部 JS/CSS | 照常工作 |
| 仓库结构 | 根目录即站点根，没有 `dist/` 之类 | 输出目录填根目录即可 |

**结论：把仓库原样接上另一个静态托管，就能跑。** Vercel 那份保留不动，双份部署互不影响。

---

## 二、托管选哪个

查证结果（2026-08）：

| 方案 | 能不能用 | 说明 |
|---|---|---|
| Gitee Pages | ❌ | 已停服 |
| 阿里云 OSS / 腾讯云 COS | ⚠️ | 要**已备案的自有域名**才能开静态网站托管，门槛高 |
| **腾讯云 EdgeOne Pages（国内站）** | ✅ **推荐** | 免费；分配 `xxx.edgeone.app` 默认域名，**默认域名不需要备案**；国内 CDN 加速；可连 GitHub 自动部署 |

### ⚠️ 国内站和国际站是两个东西，别选错

这是最容易踩的坑：

- **国际站**（edgeone.ai）：注册容易，不用绑卡、不用实名，Google 账号就能登。
  **但它是海外边缘节点，国内访问不保证加速，甚至可能和现在一样慢/打不开——选它等于白做。**
- **国内站**（cloud.tencent.com）：**需要腾讯云账号 + 实名认证**（个人身份证/人脸），
  换来的是国内 CDN 加速。**要解决儿子的问题，必须走这个。**

实名这一步只有 Ray 本人能做，这也是这件事一直卡着的唯一原因。

---

## 三、Ray 要做的事（大约 15 分钟）

1. **注册 + 实名**：`cloud.tencent.com` 注册账号，完成个人实名认证（微信/支付宝人脸即可）。
2. **进 EdgeOne Pages**：控制台搜「EdgeOne Pages」→ 新建项目 → 选「从 Git 导入」。
3. **授权 GitHub**，选仓库 `Civilization-river`（注意是大写 C）。
4. **构建配置照下面填**——这一步最容易填错，本项目没有构建过程：

   | 字段 | 填什么 |
   |---|---|
   | 框架预设 | 无 / 静态站点（None / Static） |
   | 根目录 | 留空（就是仓库根） |
   | 构建命令 | **留空**（有些界面不允许空，就填 `echo ok`） |
   | 输出目录 | `.` （一个点，表示仓库根目录本身） |
   | 安装命令 | **留空** |

5. **部署**，等一两分钟，拿到 `xxx.edgeone.app` 形式的地址。
6. **实测（这一步不能省）**：让上海那边的 iPad **关掉 VPN**打开这个地址。
   - 打得开、地图画得出来 → 成了，把它添加到主屏幕
   - 打不开 → 大概率是选成了国际站，回第 1 步确认是在 `cloud.tencent.com` 而不是 `edgeone.ai`
7. **顺带验六个故事页**（v124–v132 加的，仓库根目录下的独立单文件，会随主站一起部署）：
   `xxx.edgeone.app/tang.html` · `/qin.html` · `/han.html` · `/song.html` · `/ming.html` · `/qing.html`
   —— 这六页才是直接给 Jasper 的东西，**主站没有入口链接是有意的**（实验期不导流，见
   `docs/TANG-EXPERIMENT.md`），所以只能靠直接输网址或加主屏。

### ⚠ 已知缺口：故事页目前不支持离线

`sw.js` 的缓存清单里只有 `index.html`，六个故事页既不在清单里、自身也没注册 service worker。
所以**直接打开故事页时离线不工作**，加到主屏后没网就是白屏。
这一步按计划属于「实验通过后的最小整合」（与主站入口链接同一批，见 `TANG-EXPERIMENT.md`），
**有意押后**：上了 EdgeOne 国内 CDN 之后加载又快又稳，离线的价值下降。
若实测发现网络不稳影响使用，再提前做——改动是 sw.js 加六个文件名 + 各页加两行注册 + 升 `CACHE` 版本号。

## 四、还有一个坑：站打开了，但卡片里的链接是死的

**这条独立于上面的部署，部署做完了它依然存在。**

站里每个可点的标题——文明名、大事记条目、事件名、人物名、人物卡底部的「维基百科」——
点下去都是跳**维基百科搜索页**（`zh.wikipedia.org` / `en.wikipedia.org`）。
**维基百科在国内打不开**，所以对儿子来说，这些链接全是死的。

视频那块已经做对了：中文模式优先走 B 站，只有没有 B 站源时才退回 YouTube
（YouTube 在国内同样打不开，属于同一个问题的残留）。

**需要 Ray 拍板，三个选项：**

- **A. 中文模式改走百度百科**（`baike.baidu.com/search?word=…`），英文模式保留维基。
  改动量：`index.html` 里 `wiki()` 一个函数，一行。国内能打开，内容深度不如维基但对 7 岁够用。
- **B. 什么都不改。** 儿子点链接就是白屏，但站本身的内容（六问、大事记、地点小段、地图）是完整的，
  链接只是「想深入时的出口」。
- **C. 中文模式干脆去掉外链**，标题不再可点。最干净，但也少了一条延伸路径。

**我的建议是 A**：改动只有一行，且和视频那块「中文走国内源」的做法一致，站内口径统一。

## 五、维护提醒

- 双份部署后，**push 一次会同时触发 Vercel 和 EdgeOne 两边重新部署**，不用手动同步。
- `sw.js` 是 network-first 缓存，改了缓存策略记得升 `CACHE` 版本号（`civriver-v1` → `v2`），
  否则老设备可能吃到旧缓存。两个域名各有独立缓存，互不干扰。
- 本文档的托管方案信息查证于 2026-08，**免费额度政策会变**，出问题先回官网确认当前条款。
