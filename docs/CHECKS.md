## 0. 一句话结论

这个项目的缺陷分三层。**结构层**（键对不上、双语缺一边、越界）已被 audit 68 条收住；**渲染层**（画出来不对：少一行、黑带、关不掉、标签切掉、空行）目前 **100% 靠 Ray 实机点或我手粘脚本进浏览器**，而它恰恰是最容易自动化的一层——headless 浏览器今天就能起（复用机上已有 Playwright + 系统 Chrome，实测 322 卡扫描 0.7 秒，零安装）；**内容层**（史实、中英同义、覆盖既有正确表述、假最高级）本质要人或 LLM，能自动化的只有「出候选清单」和「写作前自动把同卡/同城既有字段拼进上下文」。

建议做的事只有一件：把散在 CLAUDE.md / HANDOFF / CHANGELOG 里的手动验证脚本固化成 **一条命令 `node tools/check.js`**，改完就跑，红了就不许 commit。

## 3. 落地方案（分三步，每步独立可停）

### 第一步：`tools/check.js` —— 改完一条命令（预计 1 个 session）
```
node tools/check.js          # = build 校验 + audit + 语法 + headless smoke，任一红 → exit 1
node tools/check.js --quick  # 只跑 build+audit+语法（≈3 秒）
```
`tools/smoke.js`（headless，Playwright + 系统 Chrome）固化以下断言，全部来自 1.1 表：
- 4 态（中/英 × 浅/深）加载零 pageerror、零对外请求
- 322 卡 `panel.innerHTML` 无 undefined/NaN/[object；**且每卡行数/字段数与数据侧一致**（拦 v218「少一行」）
- 127 城 × 中英六层无空层（<20 字即报）
- 每条色带 fill ≠ rgb(0,0,0)（拦 v193）
- 所有 `[hidden]` 元素真实盒子为 0；引导层「准备好了」点完盒子为 0（拦 v226.1）
- 泳道/色带标签 bbox ⊂ 视口且两两不相交（拦 R2）
- 选轨迹/事件后目标进入视口（拦 R4）
- 列表视图同列字号一致（拦 R7）
- 3 个视口（1180 桌面 / iPad 竖 820 / 手机 390）关键入口可见可点（拦 R14）
- 城市面板容器空白 <阈值（拦 R11）
每条断言配一个**注入反例必红**的自测（HANDOFF 教训：探针没验证过等于没加）。

### 第二步：4 条新 audit 规则 + 2 个候选清单工具（半个 session）
- 规则 69：主权国家色带不得早停（R1，带限定词白名单）
- 规则 70：敏感表述口径白名单——台湾/西藏/朝鲜战争等命中位置登记在 `data/_wording.js`，新增命中即红（R3）
- 规则 71：GEO 改动后 230 城基线**新增命中**也报（R12）
- 规则 72：audit 统计行（段数/覆盖数）与上次快照比对，缩水必须解释（v118）
- `tools/lint-content.js`：只出清单不设红灯——最短 GL/小段 N 段、>150 年城市断层、假最高级句、现在时句、同名事件年份不一致
- `tools/context.js <civ|城市>`：把 q/chrono/GL/place_lore/SETTLED 打印成一屏，**写新内容前必跑**（拦最贵那类错）

### 第三步：把「记得跑」变成「不跑不行」（10 分钟）
- `.git/hooks/pre-commit`（不进仓库，本地）：跑 `check.js --quick`；改了 index.html/data 才跑全量
- CLAUDE.md 修改工作流第 2–4 步合并成「跑 `node tools/check.js`」；HANDOFF「改完必跑」同步
- 派 adversarial-verifier 时把 `lint-content.js` 输出一并给它当线索

### 明确**不**自动化的
史实真伪、因果方向、儿童文风、图片内容合格、iPad 手感——继续走「派核查员 + Ray 实机」，但**核查员开工前先拿到 check.js 全绿 + lint 清单**，让人力只花在机器查不了的地方。

## 4. 需要 Ray 拍板的一个点：Playwright 从哪来

| 路 | 做法 | 优 | 劣 |
|---|---|---|---|
| a | `NODE_PATH` 指到 codex 运行时里的 playwright 1.62 | 零安装，今天就能跑 | 寄生在 codex 目录，codex 升级可能挪走 |
| b | 项目内 `npm i -D playwright-core`（不下载浏览器，用系统 Chrome） | 标准、可控、`package.json` 只有这一个 devDependency；产品 index.html 零影响 | 违反「不引入新依赖需确认」→ 所以放这里问 |
| c | 裸 CDP（node 24 自带 WebSocket）连系统 Chrome | 零依赖 | 要自己写 200 行协议胶水，维护成本最高 |

推荐 **b**（原因：这是长期跑的验证基础设施，不该寄生在别的工具目录里；只是 devDependency，不进运行时）。你若不想加依赖，a 也能先跑起来，之后再换。
