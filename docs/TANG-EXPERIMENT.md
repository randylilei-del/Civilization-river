# 唐朝 prototype 实验（tang.html）

**这是一个产品实验，不是主站功能。** 页面本身不是交付物，**实验结果才是**。
线上地址：主站域名 + `/tang.html`（随主站一起部署，互不影响）。

## 验证什么

现在的文明卡是**参考卡**（速览/六问/大事记/地图，按信息类型组织，等人来查）。
实验假设：**7 岁孩子通过「一次回答一个他问得出口的问题」建立认知，比通过一张
分类齐全的资料卡更有效。**

六个问题（Ray 定）：唐朝在哪里 / 唐朝的时候世界上还有谁 / 为什么唐朝这么强 /
住在长安的小孩一天是什么样的 / 安史之乱为什么改变了唐朝 / 今天还能在哪里看到唐朝。

## 给 Ray 的观察清单（实测时看这三件事）

1. **他愿不愿意继续点。** 六幕能不能自己走完？走完后有没有回头重看某一幕？
   哪一幕他点得最快（可能是无聊）、哪一幕停得最久？
2. **能不能形成时间 / 空间 / 因果。** 看完**第二天**（不是当场）问两个问题：
   - 「安史之乱之后唐朝怎么了？」（期待：用自己的话说出「伤没好 / 地方不听话了」
     这类因果，而不是复述词句）
   - 「唐朝的时候，阿拉伯 / 日本在干嘛？」（期待：知道「同时还有别人」这件事本身）
3. **对照组。** 同一周找机会让他也点一次主站的唐卡，对比停留时长和他主动提的问题。

**记下他在哪里提问、在哪里走神——提问的位置比「他说好玩」有价值得多。**

## 事先说死的边界（写在结果出来之前，防事后偷改判据）

- 实验成功也**不自动**推广到 140 个文明——那是 140 × 六幕的内容成本，是另一个
  量级的决定，到时另议。
- 实验失败（他不愿点完 / 第二天什么都不记得）就删掉 tang.html，不留恋。
- 结果出来之前，不给这个页面加功能、不做动画、不做配音、不做游戏化——
  变量越多，结果越说不清是什么起了作用。

## 工程事实

- 独立单文件 `tang.html`，零依赖、中文单语（实验对象是一个孩子；英文版等实验
  有结论再说——Ray 拍板「先做中文,后面再翻」）。
- 内容来源：六问 / PLACE_LORE（西安·敦煌·北京·成都·广州|唐）/ CHRONO / PEAK 的
  已核内容改写；第 4 幕（长安日常）为新写，经独立核查（见 CHANGELOG v124）。
- **版图坐标逐字取自 `data/geo.js`**（唐 + 共和国），不是手画的——要改去主站正本。
- 进度存 localStorage（`tang_seen`），换设备/清缓存会归零，无所谓。
- 主站零改动：不 import 主站代码，主站也不知道它的存在（没有入口链接——
  **有意的**：实验期不给主站导流，测的时候直接发 URL）。
