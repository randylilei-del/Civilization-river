# 唐朝 prototype 实验（tang.html）

**这是一个产品实验，不是主站功能。** 页面本身不是交付物，**实验结果才是**。
线上地址：主站域名 + `/tang.html`（随主站一起部署，互不影响）。

## 验证什么

现在的文明卡是**参考卡**（速览/六问/大事记/地图，按信息类型组织，等人来查）。
实验假设：**7 岁孩子通过「一次回答一个他问得出口的问题」建立认知，比通过一张
分类齐全的资料卡更有效。**

六个问题（Ray 定）：唐朝在哪里 / 唐朝的时候世界上还有谁 / 为什么唐朝这么强 /
住在长安的小孩一天是什么样的 / 安史之乱为什么改变了唐朝 / 今天还能在哪里看到唐朝。

## 给 Ray 的观察清单（实测时看这三件事）

1. **他愿不愿意继续点。** 六幕能不能自己走完？走完后有没有回头重看某一幕？
   哪一幕他点得最快（可能是无聊）、哪一幕停得最久？
2. **能不能形成时间 / 空间 / 因果。** 看完**第二天**（不是当场）问两个问题：
   - 「安史之乱之后唐朝怎么了？」（期待：用自己的话说出「伤没好 / 地方不听话了」
     这类因果，而不是复述词句）
   - 「唐朝的时候，阿拉伯 / 日本在干嘛？」（期待：知道「同时还有别人」这件事本身）
3. **对照组。** 同一周找机会让他也点一次主站的唐卡，对比停留时长和他主动提的问题。

**记下他在哪里提问、在哪里走神——提问的位置比「他说好玩」有价值得多。**

## 执行安排与反馈清单(2026-09-05 与 Ray 定:**下周末 9/12–13 跑**)

要的不是「好不好玩」,是下面四样能拿来做决定的东西。反馈发飞书群 Civilization River,几行字 + 原话,不用整理。

**1. 他自己走没走完(当场记)**
- 六幕是他自己点下去的,还是被催的;哪一幕点得最快(大概率没看进去)、哪一幕停得最久;有没有回头重看。
- **他在哪里开口问问题、在哪里走神——位置比内容重要**,直接决定以后先写哪一类故事。

**2. 第二天还剩下什么(隔一天问,不当场问)**
两个问题见上面观察清单第 2 条。**记他的原话,不要概括。**三档:用自己的话说出因果(学到了)/ 复述页面词句如「藩镇割据」(记住没懂)/ 想不起来(没留下)。第二题只要知道「那时候还有别人」就算过,不要求说对名字。

**3. 对照(同一周)**:让他点一次主站唐卡,同样记待了多久、点了什么、问了什么。没有对照,好结果也说不清是不是随便什么他都愿意看二十分钟。

**4. 搜索记录(顺手)**:主站搜索框输入 `??`,会显示他搜过的词和零命中的词,截图。

**三条不要做的**:不提示答案、不连问、问题只读一遍。答不上来也是结果,比引导出来的正确答案有用。

**结果对应的决定(先说死):**

| 结果 | 决定 |
|---|---|
| 自己走完 + 第二天能用自己的话讲因果 | 故事这条路成立。唐卡亮入口按钮(下节方案第 2 阶段),IDEAS 001 第三层开始做,从他停得最久的那类问题起 |
| 自己走完 + 第二天什么都没剩 | 好玩但不留痕。不按六幕规模化,改试更短的形式再测 |
| 走不完 | 删掉六个故事页,产品方向转回「答他问的东西」,靠搜索词驱动 |
| 走完了但对照组的唐卡他也看得差不多久 | 形式不是关键,内容才是。钱花在内容上,不花在新界面上 |

## 事先说死的边界（写在结果出来之前，防事后偷改判据）

- 实验成功也**不自动**推广到 140 个文明——那是 140 × 六幕的内容成本，是另一个
  量级的决定，到时另议。
- 实验失败（他不愿点完 / 第二天什么都不记得）就删掉 tang.html，不留恋。
- 结果出来之前，不给这个页面加功能、不做动画、不做配音、不做游戏化——
  变量越多，结果越说不清是什么起了作用。

## 工程事实

- 独立单文件 `tang.html`，零依赖、中文单语（实验对象是一个孩子；英文版等实验
  有结论再说——Ray 拍板「先做中文,后面再翻」）。
- 内容来源：六问 / PLACE_LORE（西安·敦煌·北京·成都·广州|唐）/ CHRONO / PEAK 的
  已核内容改写；第 4 幕（长安日常）为新写，经独立核查（见 CHANGELOG v124）。
- **版图坐标逐字取自 `data/geo.js`**（唐 + 共和国），不是手画的——要改去主站正本。
- 进度存 localStorage（`tang_seen`），换设备/清缓存会归零，无所谓。
- 主站零改动：不 import 主站代码，主站也不知道它的存在（没有入口链接——
  **有意的**：实验期不给主站导流，测的时候直接发 URL）。

## 实验通过后的入口方案(2026-08-09 与 Ray 议定,分三阶段)

1. **实验期(现在)**:不链接。主站零入口,直接发 URL——测的是主动点击意愿,导流会污染测量。
2. **通过后(最小整合)**:入口长在**文明卡**上,不放主页——唐卡顶部加「🏮 六个问题看懂唐朝」按钮,
   tang.html 底部加「去看整条文明长河 →」回链;`sw.js` 缓存清单加上 tang.html(离线可看)。
   哪个文明有故事页哪张卡亮按钮,**做一个亮一个,永远不出现空承诺**——这也是不放主页总开关的理由:
   「小朋友模式」那种开关等于承诺整站两套浏览方式,只有一个唐朝时挂它比没有更糟。
3. **规模化(若干个文明之后)**:才动架构——`story.html` 壳 + `data/story_<文明>.js` 内容表走 build 管线,
   与主站数据同一套核查纪律。**现在不预建。**

## 多受众路径(15 岁版 / 成人版,2026-08-09 与 Ray 议定)

**换受众贵在重写,不在技术。** 问题本身随受众换:7 岁问「是什么」(长安小孩一天怎么过),
15 岁问「为什么」(节度使怎么从方案变成问题、科举对寒门实际开放几分),成人问「争议」
(盛唐叙事的建构、唐宋变革论)。每版都要走「写 → 核查 → 改」。

- **fact 层白拿**:版图/大事记/硬数字/底图受众无关,三版共用一份,改一处全对。
- **组织方式**:`data/story_tang_7.js` / `story_tang_15.js` 按「文明 × 受众」入数据管线 + 共用壳页;
  7 岁版届时从 tang.html 迁入(手法同当年迁 PEAK)。
- **纪律**:新版本对历史解释**加深不改判**(以站内已拍板 interpretation 为准);引入新因果断言走核查;
  AI 可调语言与难度,不绕过知识层自由发挥。
- **触发条件**:真实第二受众出现才动手,不提前建。最现实的第二受众是内生的——**Jasper 会长大**,
  7 岁版本来就有保质期。

## 实验出结论后,顺带要重看的一条

`docs/IDEAS.md` 的 001(让孩子能按「他自己接触到的东西」查到答案)——它的层二层三答案
取决于本实验的结论:如果「问题驱动」被证明有效,故事级颗粒的做法就跟着变。
**实验一收口就把它拿出来一起讨论。**
